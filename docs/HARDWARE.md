## 2. 실물 확인표 (팔마다)

| 항목 | 확인 방법 | 공식 일반 구성(참고) | 리더 | 팔로워 |
|---|---|---|---|---|
| 통신 보드 모델 | 보드 인쇄, 연결 후 `scripts/so101 ports`의 VID:PID | 원 BOM은 Waveshare 버스 서보 어댑터. LeRobot 문서: Waveshare 보드면 점퍼 2개를 `B` 채널(USB)로 | 미확인 | 미확인 |
| 보드 USB 단자·모드 점퍼/스위치 | 보드 확인, 제조사 문서 | 위와 같음 | 미확인 | 미확인 |
| 모터 모델·전압·기어 | 각 모터 라벨(ID 1~6) | 팔로워 STS3215 1/345(C001) 6개. 팔로워 모터는 7.4V판과 12V판이 있다. 리더(SO101)는 7.4V, 1·3번 1/191(C044), 2번 1/345(C001), 4·5·6번 1/147(C046) | 미확인 | 미확인 |
| 어댑터 출력 정격(V, A)·극성 | 어댑터 라벨 | 원 BOM: 7.4V 모터 팔은 5V 어댑터, 12V 모터 팔은 12V 5A 이상 | 미확인 | 미확인 |
| 어댑터↔보드↔모터 전압 호환 | 보드·모터 제조사 안내, 판매자 안내 | **라벨 숫자를 단순 대입하지 않는다**(예: 7.4V 모터에 5V 어댑터가 공식 구성) | 미확인 | 미확인 |
| 내부 배선 | 육안 | 보드 → 1번(shoulder_pan) → … → 6번(gripper)을 3핀 버스 케이블로 데이지체인 | 미확인 | 미확인 |
| 물리 라벨(장치 ID) | 라벨 부착 | `configs/robot.local.yaml`의 id와 같게(예: so101_leader_a) | 미확인 | 미확인 |
| 책상 고정·작업 반경 | 클램프, 주변 정리 | — | — | 미확인 |
| 전원 차단 수단 | 어댑터 스위치/DC 잭 위치 | 손 닿는 곳 | — | 미확인 |

**배선 원칙**
- 리더와 팔로워는 각각 **별도 보드·별도 USB·별도 전원**을 쓴다. 두 어댑터에 라벨을 붙여 섞이지 않게 한다.
- 팔 안의 모터 연결은 **데이지체인**이다. 모든 모터가 3핀 버스 케이블로 같은 전원선과 데이터선을 공유하는 병렬 버스이며, 전원을 직렬로 연결하는 구조가 아니다.
- 조립된 키트는 분해하거나 ID를 초기화하지 않는다. 먼저 `probe`로 상태를 확인한다.

## 3. 포트 식별

- 서보 전원 없이도 USB 장치가 보이는지는 보드마다 다르다. 실제 보드로 확인한다.
  - 공식 문서는 USB와 전원을 연결한 상태에서 `lerobot-find-port`를 안내한다.
  - 전원 없이 보이는 보드라면 전원 투입 전에 식별하는 편이 안전하다.
- `scripts/so101 ports`로 by-id와 serial을 본다.
  - 보드마다 serial이 고유하면 by-id를 쓴다.
  - serial이 없거나 중복이면 by-path를 쓰고, 항상 같은 USB 단자를 쓴다.
- 친구 PC 등 다른 PC에서는 포트를 다시 확인한다(경로를 복사하지 않음).

## 4. 모터 상태와 설정

- `scripts/so101 probe <role>`은 읽기 전용이다. ping, 모델 번호, 펌웨어, 현재 위치, 토크, 동작 모드, 보정 레지스터를 읽는다.
- 6개가 응답하고 모델이 일치하면 **setup-motors를 건너뛴다.**
- 정상 응답은 "해당 ID가 응답했다"는 뜻일 뿐이다. 중복 ID 부재, 관절 물리 배치, 6개 실물 존재를 완전히 증명하지 않는다. 판매자 정보, 라벨, 관절별 작은 움직임 확인과 함께 판단한다.
- 응답이 없으면 다음 순서로 확인한다.
  1. 전원(어댑터 LED·전압)
  2. 케이블(보드↔1번, 체인 각 연결)
  3. 보드 모드(점퍼)
  4. 포트
  5. `probe --scan`(공식 `scan_port`: 호스트 포트 baud만 바꿔 broadcast ping, 모터 EEPROM에 쓰지 않음)
- ID 누락·충돌이 확인된 경우에만 `scripts/so101 setup-motors <role>`(공식)를 실행한다.
  - 안내에 따라 gripper부터 **모터 하나만** 보드에 연결하고 Enter를 누른다. ID와 baud(1,000,000)를 그 모터에 쓴다.
  - 전원 켜진 상태의 케이블 재배선은 보드·모터 제조사 지침을 따른다.
- 펌웨어 버전이 서로 다르면 공식 `connect`의 handshake가 실패한다(calibrate/teleop 불가).
  - 갱신은 Feetech 공식 도구로 사용자가 판단한다.
  - 펌웨어 차이만으로 초기화나 설정을 강제하지 않는다.

## 5. 보정

공식 `lerobot-calibrate`로 보정한다(`scripts/so101 calibrate <role>`).

- 팔로워는 연결 시 공식 configure가 토크를 켜고, 재보정에서 토크를 끈다. 이때 팔이 처질 수 있으므로 받친다.
- 파일 위치(공식 규칙):
  - `calibration/robots/so_follower/<id>.json`
  - `calibration/teleoperators/so_leader/<id>.json`
- 파일 형식은 관절별 `id`·`drive_mode`·`homing_offset`·`range_min`·`range_max`다. `id`는 모터 ID이고, 파일 이름은 장치 ID다.
- 공식 `is_calibrated`는 모터 레지스터의 homing_offset·range_min·range_max와 파일을 비교한다. 다르면 공식 teleop이 Enter 프롬프트로 파일을 모터에 쓰거나 보정을 시작한다. 래퍼 teleop은 이 경우 실행을 거부한다.

### 보정 백업·복원

```bash
# 백업: 작업공간 밖, 여유 있는 위치(외부 저장소 등)에
tar czf <백업 폴더>/so101_calibration_$(date +%Y%m%d).tar.gz -C ~/so101_ws calibration
# 복원(같은 물리 팔을 다른 PC로 옮긴 경우)
tar xzf <백업 파일> -C ~/so101_ws
```

복원 후 다음을 확인한다.
1. `configs/robot.local.yaml`의 `id`가 백업과 **같은 이름**인지 본다(물리 라벨 대조).
2. `scripts/so101 probe both`에서 "보정 파일 상태: match"가 나오는지 본다.
3. 다른 팔에는 재사용하지 않는다.
4. 파일이 없으면 다시 보정한다. 보정값은 모터 EEPROM에도 있지만, 공식 코드는 파일이 없으면 보정을 시작한다.

## 6. 시리얼 간섭 패키지

- `brltty`: 일부 USB 시리얼 장치를 점자 단말로 오인한다. 보드를 연결했는데 장치가 곧 사라지고 `journalctl -k`에 brltty가 보일 때만 `sudo apt remove brltty`를 검토한다.
- `ModemManager`: 새 ttyACM 장치를 탐색하며 잠시 점유할 수 있다. `doctor --scope hardware`가 점유 프로세스로 보고할 때만 해당 VID:PID에 `ENV{ID_MM_DEVICE_IGNORE}="1"` udev 규칙 추가를 검토한다.
- 설치되어 있다는 사실만으로 제거·중지하지 않는다.

| PC | brltty | ModemManager | 실제 간섭 관찰 |
|---|---|---|---|
| 연구실(jammin) | 설치됨(6.6) | active | 로봇 미연결, 관찰 없음 |
